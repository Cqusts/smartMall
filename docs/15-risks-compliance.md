# 15 · 风险与合规

> 电商 + AI 生成内容 + 真实用户对话数据，这三者叠加意味着合规不是可选项。
> 本文列出必须处理的合规要求和技术风险，以及每一项的处置方案。

---

## 1. 合规要求

### 1.1 AI 生成内容标识

**要求来源**：《人工智能生成合成内容标识办法》及配套强制性国家标准，要求 AI 生成合成内容添加标识。

**本项目涉及的内容**：宣传图、宣传视频、AI 口播音频、AI 客服回复。

| 内容类型 | 显式标识 | 隐式标识 |
|---|---|---|
| 宣传图 | 画面角落"AI 生成"角标 | 图片元数据（EXIF/XMP）写入生成信息 + 像素级数字水印 |
| 宣传视频 | 画面角标 + 片尾说明 | 视频元数据 + 帧水印 |
| AI 口播音频 | 无（音频难加显式标识） | 音频文件元数据 |
| AI 客服回复 | 会话界面标注"AI 助手" | Trace 记录 |

**技术落地**（见 [07 · AI 素材中心](07-asset-center.md)）：

```
asset 表三个必填字段：
  ai_label_applied  = 1   显式角标已注入
  ai_meta_applied   = 1   元数据已写入
  ai_watermark      = 1   数字水印已嵌入

状态机强制校验：
  draft → reviewing 时，若 ai_generated=1，
  则上述三字段必须全为 1，否则拒绝流转
```

**把校验放在状态机而不是业务代码里**——任何路径创建的素材都绕不过去。这是合规要求的技术保障方式。

⚠️ **元数据会在传输中丢失**：很多平台上传图片时会剥离 EXIF。因此不能只靠元数据，**数字水印（像素级）是更可靠的隐式标识**，且三种标识必须同时具备，不能只做一种。

### 1.2 广告法

**风险点**：AI 生成的文案与客服话术容易出现违规表述。

| 违规类型 | 示例 | 处置 |
|---|---|---|
| 绝对化用语 | 最好、第一、顶级、唯一、国家级、最高级 | 词表拦截 + 重新生成 |
| 虚假宣传 | 无依据的成分含量、功效 | 与商品结构化属性强制比对，冲突则拦截 |
| 医疗功效 | 治疗、根治、疗效、抗菌（未取得资质） | 直接拦截 |
| 引人误解的比较 | "比某某品牌好" | 竞品词拦截 |
| 虚构的用户评价 | AI 编造的"买家反馈" | **禁止生成此类内容** |

**统一规则引擎**：`apps/python/ai-common/compliance/`，被客服 Agent 的 PostCheck、运营 Agent 的文案检查、切片话术规整化共用。规则更新一处生效。

**词表来源与维护**：初始词表基于广告法明令禁止用语整理，运营可在后台增删，变更有审计记录。

### 1.3 数据来源合规

| 数据源 | 合规要求 | 处置 |
|---|---|---|
| **JDDC / ECD 公开数据集** | 学术授权，通常限研究用途 | 走正式授权申请；**授权范围写入 `ds_source` 表**；商用前需重新确认许可 |
| **自有系统真实对话** | 用户告知与同意；个人信息保护 | 隐私政策中明示"对话数据可能用于服务改进与模型训练"；PII 脱敏后使用 |
| **网络爬取的客服对话** | 🔴 **高风险** | **不采用**——平台服务协议通常禁止，且涉及第三方用户隐私 |
| **LLM 合成数据** | 需符合所用模型的服务条款 | DashScope / DeepSeek 的输出用于训练自有模型需确认条款 |

⚠️ **原始需求中提到"网上真实的客服聊天数据"，本方案明确不走爬取路线**。替代方案是三条腿策略（公开数据集 + 合成数据 + 自有回流），见 [00 · 项目全景](00-overview.md) 第 4 节。这不是能力限制，而是风险控制——爬取的数据一旦进入训练集，后续无法剥离。

### 1.4 个人信息保护

| 要求 | 落地 |
|---|---|
| 最小必要 | Trace 中不存储用户真实姓名、手机号、地址 |
| 脱敏 | 数据中台关卡①强制 PII 脱敏，原文加密存 `raw_content`，仅审计角色可解密 |
| 存储期限 | 原始对话保留 1 年，超期归档或删除 |
| 用户权利 | 提供数据删除接口，删除请求需级联清理 ODS/DWD/DWS/向量库 |
| 越权防护 | `get_order_status` 强制校验订单归属（见 [11 · Agent 集群协作](11-agent-cluster.md)） |

**级联删除是最容易遗漏的**：用户要求删除数据时，除了业务库，还要清理 ODS 原始记录、DWD 明细、由该对话生成的 `knowledge_item`、Milvus 中的向量、以及已发布的数据集快照。需要一个 `data_erasure` 任务按 `source_ref` 全链路追溯清理。

### 1.5 肖像权与声音权

| 场景 | 风险 | 处置 |
|---|---|---|
| 虚拟试穿使用真人模特底图 | 肖像权 | 使用已授权素材库，或用 AI 生成的虚拟模特 |
| CosyVoice2 克隆主播音色 | 声音权（人格权） | **必须取得主播书面授权**，授权范围与期限记录在案 |
| 直播切片包含主播影像 | 肖像权 | 主播合同中约定内容二次使用权 |

**AI 生成的虚拟模特是更安全的选择**——无肖像权问题，且形象可复用、风格统一。代价是需要额外的一致性控制（固定 LoRA + 固定 seed）。

### 1.6 生成内容的真实性

**这是电商场景特有的风险**：AI 生成的商品图必须是**真实商品**，不能是"想象中的商品"。

| 措施 | 说明 |
|---|---|
| 强制 IP-Adapter | 生成图必须以真实商品实拍图为视觉锚点 |
| CLIP 相似度闸门 | 生成图与实拍图相似度 ≥ 0.75，否则不允许进入审核 |
| 图生视频而非文生视频 | 视频首帧必须是真实商品图（见 [06 · 运营 Agent](06-agent-marketing.md)） |
| 属性一致性检查 | 文案中的材质/规格必须能在商品结构化属性中找到 |
| 人工审核闸门 | 素材上线前必须人工确认 |

**这不是效果优化，是合规要求**——展示与实物不符的商品图构成虚假宣传。

## 2. 技术风险登记册

| # | 风险 | 概率 | 影响 | 处置 |
|---|---|---|---|---|
| R1 | JDDC 数据集授权申请周期长或未获批 | 中 | 高 | M0 期间提前申请；并行准备 LLM 合成数据作为冷启动备选 |
| R2 | 单卡 24G 显存不足，Wan2.2 或训练跑不动 | 中 | 高 | 降级方案：Qwen3-4B 微调；视频走云端 API；或按需租 48G 卡 |
| R3 | 直播语义分段准确率不达标 | 高 | 中 | FunClip Gradio 作为人工兜底；先保证链路通，再迭代算法 |
| R4 | 考核 Judge 校准不通过（ρ < 0.7） | 中 | 高 | 先修 Rubric（歧义是主因）；换更强模型；增加 few-shot |
| R5 | 微调导致 RAG 忠实度退化 | 中 | 高 | 三条防退化红线做门禁；`lora_rank` 调小；训练数据参数化 |
| R6 | DPO 过拟合导致回复退化 | 中 | 中 | 只跑 1 epoch；`pref_beta` 调大；`rejected` 中混入过短负例 |
| R7 | 知识库出现冲突或过期知识 | 高 | 中 | `dag_kb_staleness_check` 每日检查；`valid_to` 强制过滤 |
| R8 | 人工审核成为吞吐瓶颈 | 高 | 中 | 主动学习只推低置信度样本；审核界面优化（快捷键、属性对照标红） |
| R9 | API 成本超预算 | 中 | 中 | 闲聊分流小模型；考核抽样；成本告警（超基线 150%） |
| R10 | MinIO 归档导致对象存储无维护 | 已确认 | 中 | **已规避**——改用 SeaweedFS 或阿里云 OSS |
| R11 | FLUX.1-dev 非商用许可 | 已确认 | 中 | 演示用 dev，商用切 FLUX.1-schnell 或 Qwen-Image |
| R12 | 客服 Agent 越权查询他人订单 | 中 | 高 | MCP Server 层强制校验订单归属；渗透测试 |
| R13 | Prompt 注入导致 Agent 泄露系统提示或越权 | 中 | 中 | 输入 Guard；工具白名单；输出检查 |
| R14 | 长耗时任务触发 Kafka rebalance 重复投递 | 高 | 中 | 消费后立即 ack，任务状态用数据库管理 |
| R15 | 评测集与训练集污染 | 中 | 高 | `filter_sql` 硬性排除评测集 `session_id` |
| R16 | 单机部署，任一组件故障全站不可用 | 高 | 低 | 作品集定位可接受；关键路径有降级预案 |

## 3. 安全清单

### 3.1 Agent 安全

| 攻击面 | 防护 |
|---|---|
| Prompt 注入（用户输入伪装成指令） | 输入 Guard 检测；System Prompt 与用户输入用明确分隔符；工具调用不依赖 prompt 授权 |
| 越权数据访问 | MCP Server 层参数校验（订单归属、用户绑定） |
| 工具滥用（诱导 Agent 循环调用） | 单会话单工具调用 ≤ 5 次 |
| 系统提示泄露 | 输出检查过滤系统提示特征串 |
| 恶意刷量 | 网关限流；单用户会话频次限制 |

### 3.2 数据安全

| 项 | 措施 |
|---|---|
| PII | 关卡①强制脱敏；原文加密存储 |
| 数据库访问 | 服务账号最小权限；生产库禁止直连 |
| 对象存储 | 素材 URL 用签名 URL，有效期 2 小时；禁止目录遍历 |
| API Key | 全部走环境变量 / 密钥管理，不入库不入 Git |
| 审计日志 | MCP 工具调用、数据集发布、素材审核、评分申诉全量记录 |

### 3.3 内容安全

| 项 | 措施 |
|---|---|
| 用户输入 | 敏感内容检测（涉政、色情、暴力） |
| AI 输出 | PostCheck 合规检查 |
| 生成素材 | VLM 缺陷检测 + 人工审核 |
| 直播话术 | 规整化时过滤违规表述 |

## 4. 上线前检查清单

正式对外提供服务前必须逐项确认：

**合规**
- [ ] AI 生成素材的三类标识全部实现并强制校验
- [ ] 广告法违禁词库完整，规则引擎在三处（客服/文案/切片）全部生效
- [ ] 数据来源授权文件齐备，授权范围记录在 `ds_source`
- [ ] 隐私政策已更新，明示数据用于服务改进与模型训练
- [ ] 音色克隆与肖像使用的书面授权已取得
- [ ] 数据删除接口可用，级联清理覆盖全链路

**安全**
- [ ] 越权测试通过（用他人订单号查询被拒绝）
- [ ] Prompt 注入测试通过
- [ ] API Key 无硬编码（`git-secrets` 扫描通过）
- [ ] 对象存储签名 URL 生效，无公开可枚举路径
- [ ] 审计日志覆盖全部关键操作

**质量**
- [ ] 所有评测集指标达到门禁阈值
- [ ] 考核 Judge 校准通过（α ≥ 0.7，ρ ≥ 0.7）
- [ ] 微调模型三条防退化红线守住
- [ ] 降级预案全部验证（Milvus 挂、API 超时、VLM 不可用）

**运维**
- [ ] 备份脚本可执行，恢复演练通过
- [ ] 监控看板可用，告警规则生效
- [ ] 成本告警阈值设置
- [ ] GPU 调度器的降级模式验证通过

## 5. 已知的方案局限

诚实地列出本方案做不到的事，避免误判：

| 局限 | 说明 |
|---|---|
| 单机部署无高可用 | 任一组件故障即全站不可用。作品集定位下可接受，生产需重新设计 |
| 无多租户隔离 | 数据模型未预留 `tenant_id`，多商家场景需改造 |
| 24G 卡的能力天花板 | 无法运行大参数量的 VLM 与视频模型，效果上限受限于可跑的模型 |
| 知识时效性依赖人工 | `valid_to` 需人工设置，自动识别时效性的能力有限 |
| 考核 Judge 存在偏差 | 已通过校准与交叉验证缓解，但无法完全消除 |
| 微调只解决风格 | 不提升知识准确性——那是 RAG 的职责 |
| 中文单语 | 多语言场景需重新选型 embedding 与生成模型 |
| 冷启动依赖公开数据集 | 公开数据集的商品类目与自有商品不完全匹配，需要合成数据与人工补写填补 |
